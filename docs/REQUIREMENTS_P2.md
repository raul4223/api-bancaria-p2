## Matriz de endpoints

`JWT` significa `Authorization: Bearer ...`. `Atendimento` exige JWT mais `X-Service-Session-Id`. Toda rota `/api/v1` é protegida por JWT, exceto o login. Movimentações também exigem `Idempotency-Key` UUID.

## Evidências de validação local

- `npm run typecheck`, `npm run lint`, `npm run build` e `npm test`: aprovados. A suíte completa aprovou 22 testes unitários e 5 cenários E2E (incluindo TED fora do horário e limite noturno do PIX com relógio simulado).
- `npx prisma validate`: schema válido; `npx prisma migrate status`: schema `bank_api` atualizado; `npm run db:seed`: executado com sucesso no banco local isolado.
- O E2E cobre login/JWT, os três CRUDs, atendimento, contas, movimentos, idempotência sequencial e simultânea, rollback, isolamento, bloqueios, extrato, conciliação e OpenAPI.
- Health HTTP real: `/health` 200 e database connected; `/docs` 200; `/openapi.json` válido com 30 operações; login HTTP 200. O token não foi impresso.
- Roteiro da demo (`docs/DEMO_CHECKLIST.md`) executado via HTTP real com a API compilada, num banco MySQL 8.4 novo e descartável (`bank_api_demo`, removido depois): cadastro de A e B, atendimentos, contas, chave Pix, favorecido TED, depósito, INTERNAL, PIX, TED com tarifa e saque. Resultado: A1 R$ 30,00, A2 R$ 10,00, B1 R$ 50,00, SYSTEM −R$ 90,00, soma dos saldos 0 e conciliação `balanced: true`. Num domingo, a TED foi recusada com `TED_OUTSIDE_BUSINESS_HOURS` e aceita depois de reiniciar com `TED_BUSINESS_HOURS_ENABLED=false`, como prevê o checklist. Também conferidos: repetição idempotente (200), chave reutilizada com outro payload (409), saldo insuficiente sem alterar saldo, bloqueio e reativação de B1, atendimento fechado (403) e bloqueio após 5 senhas erradas (423).
- Instalação limpa numa cópia temporária sem `.env`, `node_modules` ou cliente gerado: `npm ci` no Node 24.15.0, `npm run build`, `npm run typecheck` e `npm run lint` aprovados.
- A validação final usou MySQL 8.4.13 no container Compose `api-banco-p2-isolated-mysql-1` e `bank_api_test`; o container/volume anterior em 3306 foi preservado. Migrations, seed, health HTTP e suíte completa passaram nesse MySQL.
- `npm audit --omit=dev`: zero vulnerabilidades de produção. O audit completo relata 7 alertas moderados de `minimatch@10.2.6`, dependência transitiva de desenvolvimento do `typescript-eslint`; o GHSA cobre versões anteriores à 11.0.1, mas o consumidor declara `^10.2.2`. Não apliquei override de major incompatível nem atualização forçada do lint.
